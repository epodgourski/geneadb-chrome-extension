## [2026.06.06.06] — 2026-06-06

### Изменено
- **Скачивание серии перенесено в service worker** (`background.js`). Раньше цикл
  крутился в попапе и **прерывался при закрытии/потере фокуса попапом** (Chrome
  выгружает popup). Теперь попап лишь запускает процесс и показывает прогресс,
  а навигация по кадрам, сбор ARK и скачивание выполняются в фоне и **продолжаются
  даже после закрытия попапа**.
  - Протокол: `startSeries` / `cancelSeries` / `getSeriesState` + сообщения
    `seriesProgress` для обновления прогресса в попапе.
  - При повторном открытии попапа во время активного скачивания прогресс
    восстанавливается из состояния фонового процесса.
  - Отмена — повторным нажатием кнопки (как и раньше).

## [2026.06.06.03] — 2026-06-06

### Исправлено
- **ARK всегда берётся в формате `3:1:XXXX`** (имя файла — часть после `3:1:`,
  например `3QHK-V7TF-73W2`). На сериях, где `id` ячейки служебный
  (`grid-item-TH-...`), нужный `3:1:`-ARK теперь извлекается из `src` миниатюры,
  а не из `id`. Источники ARK по приоритету: `id` ячейки → `src` миниатюры →
  вложенный `id`. Если `3:1:`-ARK не найден, кадр пропускается (без появления
  `TH-...` в имени файла).
- **Главный детектор серии** — `input[type="number"][min="1"]` с `max > 1`:
  единственный признак, надёжно срабатывающий во всех проверенных случаях
  (`groupId` присутствует не всегда, число отрендеренных кадров сетки не равно
  общему из-за виртуального скролла).

## [2026.06.06.01] — 2026-06-06

### Добавлено
- **Пакетное скачивание серии снимков** с FamilySearch
  - Кнопка **«Скачать серию (N)»** в UI, появляется только на FamilySearch при наличии серии (N — общее число снимков)
  - **Языконезависимая детекция** серии (не зависит от локализации интерфейса):
    - числовое поле `input[type="number"][min="1"]` с `max > 1` — основной признак серии и источник общего числа кадров;
    - параметр `groupId` в URL и наличие `[role="option"][image-index]` — вспомогательные признаки.
  - **Сбор ARK всех кадров** по техническим атрибутам, без привязки к тексту:
    - чтение сетки `[role="option"][image-index]` с прокруткой контейнера (обход виртуального скролла), `image-index` задаёт порядок кадра;
    - ARK берётся из `id` (`grid-item-<ARK>`), поддерживаются оба формата идентификаторов;
    - фолбэк-навигация кнопкой «вперёд», которая ищется по позиции относительно поля ввода (а не по `aria-label`), с чтением ARK текущего кадра.
  - К существующему имени файла добавляется числовой префикс `NN_` (ширина с ведущими нулями: 2 знака до 99 снимков, 3 знака от 100)
  - Прогресс в тексте кнопки («Скачивается 3 / 40...») и отмена повторным нажатием
  - Пауза 400 мс между скачиваниями, чтобы не перегружать сервер
- Чтение DOM активной вкладки через `chrome.scripting.executeScript` (используются уже имеющиеся разрешения `scripting` + `activeTab`)

### Изменено
- Логика загрузки вынесена в переиспользуемую функцию `requestDownload`; серия использует тот же Service Worker с `credentials: 'include'`, что и одиночное скачивание FamilySearch

## [2026.03.28.01] — 2026-03-28

### Добавлено
- Новый источник **Яндекс Архивы** (`ya.ru/archive/catalog/{каталог}/{N}`)
  - Публичный доступ, авторизация не требуется
  - Получение ID изображения через fetch текущего URL и поиск `"thumb":{"path":"..."}` в ответе
  - Скачивание оригинала через `ya.ru/archive/api/image?id=...&type=original`
  - Имя файла: `fNNNN.jpeg` (номер страницы, дополненный нулями до 4 знаков с префиксом `f`)
- `host_permissions` для `ya.ru` в `manifest.json`

### Изменено
- Архитектура расширения: добавлена поддержка `needsPageScan` — опциональный шаг `scanPage(url)` перед парсингом для источников, требующих получения данных со страницы
- `parseUrl` и `processCurrentTab` принимают параметр `extra` с данными, полученными при сканировании
- `processCurrentTab` стал асинхронным (`async`)
- Убрано дублирование `detectSource` в обработчике `DOMContentLoaded`
- Исправлена неиспользуемая переменная `response` в `downloadImage`
